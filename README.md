> # به‌مسیر — سامانهٔ مدیریت ناوگان
>
>    نسخهٔ متصل به بک‌اند Node.js و دیتابیس MySQL.
>    داده‌های عملیاتی این نسخه در دیتابیس نگهداری می‌شوند، نه localStorage مرورگر.
>    نگهداری محلی ترجیح ظاهر، مانند تم، با این موضوع متفاوت است.
>
>    ## وضعیت فعلی
>
>    اجرای محلی روی ویندوز، اتصال به MySQL، ورود کاربران و عملیات اصلی
>    به‌صورت دستی آزمایش شده‌اند. پشتیبان‌گیری و بازیابی آزمایشی نیز انجام شده است.
>
>    این موارد به معنی تکمیل همهٔ آزمون‌ها، تأیید امنیت جامع یا آمادگی تولید نیستند.
>
>    لاگ فعلی بعضی اقدامات، فقط وقوع اقدام را ثبت می‌کند و الزاماً
>    اطلاعات کامل قبل و بعد یا امکان بازیابی نسخهٔ قبلی را ندارد.
>
>    ## ساختار پروژه
>
>    - public/: رابط کاربری و فایل‌های قابل ارائه به مرورگر
>    - backend/: API، احراز هویت و قواعد عملیاتی
>    - sql/: اسکریپت‌های ساخت و ارتقای دیتابیس
>    - windows/: ابزارهای اجرای محلی و پشتیبان‌گیری
>    - tests/: آزمون‌ها و مستندات مربوط به آن‌ها
>
>    فقط public باید به‌عنوان محتوای عمومی وب ارائه شود.
>    پوشه‌های backend، sql و private نباید از وب قابل دانلود باشند.
>
>    ## محیط فعلی
>
>    - Node.js 24
>    - MySQL 8.4
>    - اجرای محلی ویندوز
>    - نشانی فعلی نرم‌افزار: <https://localhost:8443>
>
>    نسخهٔ دقیق وابستگی‌ها در backend/package-lock.json ثبت شده است.
>
>    ## اجرای محلی
>
>    بازکردن مستقیم public/index.html کافی نیست.
>    MySQL، بک‌اند و سرویس HTTPS باید فعال باشند.
>
>    در محیط ازقبل‌تنظیم‌شده، از میانبرهای محلی Start-BehMasir و
>    Stop-BehMasir استفاده کنید. میانبرها وابسته به مسیر نصب هستند
>    و در مخزن نگهداری نمی‌شوند.
>
>    اسکریپت windows/launcher-control.ps1 حالت‌های Start و Stop دارد.
>    اجرای آن به نصب پیش‌نیازها، تنظیمات خصوصی و گواهی معتبر محلی نیاز دارد.
>
>    بستن مرورگر به معنی توقف بک‌اند نیست.
>
>    ## اطلاعات محرمانه
>
>    رمزها، فایل‌های محیطی، تنظیمات اتصال، گواهی‌های خصوصی و
>    پشتیبان‌های دیتابیس نباید وارد Git شوند.
>
>    این فایل‌ها باید جداگانه و امن نگهداری شوند.
>    کلون‌کردن مخزن به‌تنهایی محیط آمادهٔ اجرا ایجاد نمی‌کند.
>
>    ## هشدار دربارهٔ دیتابیس
>
>    sql/001_schema.sql برای ایجاد اولیهٔ ساختار است؛
>    آن را دوباره روی دیتابیس موجود اجرا نکنید.
>
>    ارتقا باید با پشتیبان تازه، بررسی اسکریپت و آزمون روی دیتابیس جدا انجام شود.
>    فایل پشتیبان نیز تا زمانی که بازیابی آن بررسی نشده، تضمین بازیابی نیست.
>
>    داده‌های نمونهٔ backend/catalog.json اختیاری‌اند؛
>    اسکریپت seed را بدون بررسی روی دیتابیس موجود اجرا نکنید.
>
>    ## توسعه‌های برنامه‌ریزی‌شده
>
>    - یک سازمان با واحدهای درختی
>    - مجوزهای قابل تخصیص و محدود به واحد سازمانی
>    - تأیید چندمرحله‌ای درخواست‌ها
>    - جدول مستقل انواع خودرو
>    - تاریخچهٔ کامل‌تر و بازیابی کنترل‌شده
>    - تکمیل لاگ ورود، خروج و تلاش‌های ناموفق
>
>    این موارد صرفاً برنامهٔ توسعه‌اند و نباید پیاده‌سازی‌شده فرض شوند.
>
>    سازگاری MariaDB و استقرار نهایی روی سرور هنوز تأیید نشده‌اند.
>    GitHub محل نگهداری کد است؛ GitHub Pages به‌تنهایی بک‌اند Node.js
>    و دیتابیس این نرم‌افزار را اجرا نمی‌کند.
